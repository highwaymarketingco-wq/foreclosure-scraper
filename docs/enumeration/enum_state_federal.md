## TOP 5 NET-NEW

1. **NC OneMap statewide parcels as a name→parcel + owner-mailing resolver** — `services.nconemap.gov/secure/rest/services/NC1Map_Parcels/MapServer/1/query`. 662,251 parcels across the 11 NC counties, with `ownname` LIKE-searchable and `mailadd/mcity/mstate/mzip` on every record. This is the direct fix for the two live bugs in memory (`project_resolver_bugs_and_scdot_wall`): the dead mail spine and the ~25-30% name→parcel ceiling. It also removes the dependency on 11 separate county ArcGIS hosts for NC owner lookups. Highest value, lowest build cost — one scraper, one field map.

2. **NC OneMap parcels, absentee-owner cut** — same endpoint, `where=cntyname='X' AND mstate<>'NC' AND mstate IS NOT NULL AND struct='Y'`. **37,227 out-of-state owners of improved NC property** in-footprint, already carrying a mailable address. This is a lead SOURCE in its own right, not an enricher. Caveat: Burke County returns 0 (does not populate `mstate`) — needs a per-county coverage flag.

3. **NCDOT Right-of-Way Proposed Acquisition** — `gis11.services.ncdot.gov/arcgis/rest/services/RowMsPub/NCDOT_RowMS_ProposedAcquisition/MapServer/2`. 226,755 owner-name records statewide, no token, with sibling Parcel-Number and Deed-Book-and-Page annotation layers. 4,808 records in a Buncombe-sized envelope. Property owners facing a state taking are a genuinely new motivated-seller facet nobody in this market is working. Build note: annotation text is fragmented across rows (`MAXIMINO BUSTOS AND` / `WIFE, RUFINA SANTANA` are two records) — needs a `FeatureID`/`TextGroup` reassembly pass, and county assignment is spatial-clip only.

4. **AddressNC QA layers** — `services.nconemap.gov/secure/rest/services/AddressNC/NC1Map_Addresses/MapServer/{17,18,20,21,8,11,12}`. Floaters, Duplicate Addresses, Sub Locations, New Locations, and municipal/zip/county conflicts. The Charleston resolver work established that address-less leads are ~18% of the board; these are the state's own reconciliation outputs and are the cheapest remaining lift on that number for NC.

5. **EPA Envirofacts county-path REST** — `data.epa.gov/efservice/<table>/state_code/NC/county_name/BUNCOMBE/rows/0:N/JSON`. County is a native URL segment, no key, and the same pattern reaches RCRA, SEMS/superfund, UST/LUST, TRI, and brownfields. The existing `enrichment_environmental.py` only does ECHO radius-around-a-point, which cannot do a bulk county pull. This also backfills the SC contamination coverage that died when DHEC's GIS endpoint broke.

**Two things to act on that are not new sources:**
- **NC SoS UCC / Federal Tax Lien is a compliance wall, not a technical one.** Cloudflare 403 plus an explicit published prohibition on automated searches, with bulk sold via Data Subscription Services. Treat it exactly like SC PublicIndex: do not build a bypass. If UCC/FTL data is wanted, price the subscription.
- **The OpenFEMA `$`-encoding gotcha.** `?$filter=…` returns a Drupal 404 page with a 503; `?%24filter=…` returns JSON. This is the same silent-death failure mode as the Column source (`project_column_source_silent_death`) — the repo already calls these endpoints, so it is worth checking whether the existing FEMA enrichers are quietly returning zero.

Also worth recording: **`docs/run_meta.json` `by_source` is empty**, so there is currently no machine-readable way to answer "is source X already producing." Every NEW/scraped call above came from reading the scraper tree by hand.
