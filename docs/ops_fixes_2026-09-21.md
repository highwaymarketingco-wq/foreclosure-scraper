## 2. O3 The lock is enforced and the payload set is sealed

### What changed

**`write_artifact` refuses without the lock.** `src/foreclosure_scraper/web_artifact.py`, `require_board_lock` (line 587), called first in `write_artifact` (line 2455) before any byte is written. It passes when `BOARD_LOCK_BYPASS=1` (explicit, logged), when the docs directory is not the live one (a scratch board shares nothing), or when `FORECLOSURE_BOARD_LOCK_HELD` names this repo's lock and, if the holder exported a token, the token on disk still matches. The message names the fix (`scripts/with_board_lock.sh <owner> -- <command>`).

**`scripts/with_board_lock.sh <owner> [--wait S] [--max-runtime S] -- <command>`** runs any command under the lock. This is how the 54 unlocked writers run without editing them. Exit 75 when the lock is busy, 76 when the memory gate refuses.

**Changed-since-load.** `read_board_records` (line 856) records `(file read, st_mtime_ns, st_size)`; `_check_not_changed_since_load` (line 779) aborts the write when the plain `listings.json` changed after this process loaded it. It does not fire when `load_board` read the `.gz` twin (fresh clone, CI, restore) or when the rows were loaded from a different docs directory; stamps are keyed by the loaded directory. A process that never loaded has nothing to compare.

**Manifest.** `docs/board.manifest.json`, written last by `write_artifact` (`write_manifest`, line 2403): size, sha256 and record count of `listings.json`, `listings_detail.json`, both `.gz` twins, both slim files, `run_meta.json` and every shard. `load_board` and `read_board_json` verify the file they read (`_choose_board_file`, line 721) and refuse the plain-over-gz preference when the plain file disagrees: the manifest-matching twin is used, and if neither matches `BoardIntegrityError` is raised. The detail sidecar must have the same number of rows as the board when a manifest exists. `_load_prior_details_by_key` no longer swallows an integrity error (it used to return `{}` and let the next write publish an empty sidecar over a torn set). The manifest is in `scripts/board_payload.sh` (`board_payload_paths`) but excluded from the change gate like `run_meta.json`, because its `written_at` moves on every write.

**Dropped rows.** `load_board` (line 906) counts and logs every row `Listing.model_validate` rejects (first 200 to `logs/board_load_dropped.jsonl`, next to the loaded board) and raises `BoardLoadDropError` above 0.1% (`BOARD_LOAD_MAX_DROP_RATE`; `BOARD_LOAD_ALLOW_DROPS=1` loads anyway; `load_board(docs, max_drop_rate=1.0)` for a caller with its own recovery, which is what `patch_vision_gemini.load_board_no_shrink` does in the patch).

**Tools.** `scripts/board_manifest.py`: `--verify` (default), `--verify --quick`, `--rebuild` (takes the lock), `--validate-rows`.

## 3. O4 Health is honest, failures are loud, jobs report

### run_meta health

`write_artifact` (`web_artifact.py` around line 2790): `health_as_of` is stamped when the writer computed its own `source_status`, otherwise carried forward unchanged from the first write that computed it (env `BOARD_HEALTH_AS_OF` seeds it once). `health_carried_from` now names that origin, not the previous write. ### Per-source last success (audit A2)

`run_meta.source_last_success`: `{slug: iso}`. Stamped from the writer's own `source_status` (entries that start with `OK`) and from `summary["source_refreshed"]` (a list or a dict of slug to timestamp). Untouched sources keep their own last success across writes. The family runner passes the sources whose scrape returned rows; the daily API patch passes the sources that returned a healthy pull (3 rows or more).

### main.py exit codes (`src/foreclosure_scraper/main.py`)

### Watcher

`scripts/job_watch.py` (stdlib only, Python 3.9, runs under `/usr/bin/python3`). Alerts, as a macOS notification and a line in `logs/job_alerts.log`, when a job has no healthy outcome inside its window (48 hours by default; 200 for weekly jobs; 240 for `full_run`), when a job's last three runs all failed, or when `scripts/check_payload_size.py` finds a payload over 80 MiB or the deployed site near the Pages limit. ## 7. O9 Memory gate and measurements

`board_memory_gate` (Python) and `board_mem_gate` (`scripts/board_lock.sh`): swap used above 3,072 MB or free plus inactive below 1,024 MB. Modes via `BOARD_MEM_GATE`: `warn` (log a job event and proceed), `enforce` (wait up to `BOARD_MEM_GATE_WAIT`, 900 s, then refuse), `off`. Thresholds: `BOARD_GATE_SWAP_MB`, `BOARD_GATE_FREE_MB`. The gate runs before the lock is taken (waiting must not hold the lock) and also guards `parcel_cache_refresh.sh` and the family scrape phase.

**The default is `warn`, not the enforcing behaviour that was asked for, on purpose.** Measured on this Mac at 12:40 with one job running: swap used 7,015 MB (7,207 MB by the probe a few minutes later; 6,344 MB of 7,168 MB at 14:00). Against a 3,072 MB limit that is a permanent refusal, so enforcing would skip every scheduled job every day (I hit exactly that when a test of the shell gate waited its full 900 seconds). The plist templates set `BOARD_MEM_GATE=warn` explicitly. Read the `mem_gate` lines in `logs/job_events.jsonl` for a week, pick thresholds this machine can meet, then set `enforce` in the plists. **Decision for the lead.**

Each job records swap-out delta (pages times page size) and peak RSS at its end (`/usr/bin/time -l` through `job_run`). Test hooks: `BOARD_GATE_FAKE_SWAP_MB`, `BOARD_GATE_FAKE_FREE_MB`.

**Not done:** passing the loaded detail into `write_artifact` (one fewer 1.1 GB copy), streaming the JSON write, and the AC-power requirement for runs over an hour.

## 8. O11 Lock design

`logs/.board.lock/pid` is now six lines: pid, owner label, start epoch, heartbeat epoch, max runtime seconds, token (old readers read lines 1 and 2). `logs/.board.lock/children/<pid>`: a writer running inside a wrapper's lock registers itself when it loads or writes, so the lock survives a killed wrapper. Stale means: the owner and every registered child are dead, or a live holder is older than its max runtime plus 30 minutes (default 6 h; the full run declares 72 h; the daily job 4 h). Every break and skip is a job event (`lock_break`, `lock_skip`, with holder and heartbeat age). The heartbeat (Python thread, shell background subshell, every 60 s) is diagnostic only: a 1.1 GB `json.loads` holds the GIL long enough on this Mac that a quiet heartbeat proves nothing.

**Fencing.** Each acquisition has a random token exported as `FORECLOSURE_BOARD_LOCK_TOKEN`. `write_artifact` and reentrant children compare it with the token on disk, so a hung holder whose lock was broken and re-taken cannot write; the old holder's exit does not delete the new holder's lock.

**Tests:** `tests/test_board_integrity.py` (Python), `tests/test_ops_shell.py` (shell, in `sh`, `bash` and `zsh`, and both implementations against each other). `tests/test_publish_plumbing.py` was updated for the six-line record.
