## Two systemic findings beyond the per-source table

- **The `0 <STREET>` merge bug.** `dedupe._strong_sigs` builds a `("s", canon_street, county, state)` signature and union-merges on it. Vacant/land parcels publish situs with house number `0`, so 33 legally distinct parcels on `0 SOUTHPORT RD` become one lead. Measured on Spartanburg's vacant registry: 4,590 addressed rows → 3,374 canonical streets. `_strong_sigs` already blacklists addresses starting with `vacant`/`lis pendens`/`property in`; it does not blacklist a `0` house number. This silently suppresses ~1,216 Spartanburg leads and will do the same to `pickens_delinquent_parcels` (2,161 rows, same shape) the moment it lands.
- **Board shrinkage between full runs.** The 07-31 run logged `orchestrator.board_persist merged_count=32143`, but the artifact committed two days later was 25,576 and today's is 25,552 — roughly 6,500 leads short of what that run persisted. The mechanism is **unmeasured**; I did not run anything that writes the board. Worth its own investigation, because it caps capture rate for every source in this audit regardless of scraper health.
